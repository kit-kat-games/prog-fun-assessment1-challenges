Challenge 1 - Reflection
Context:
This challenge asks me to build an application that uses std::cout to print out a given boat ASCII art. This involved using the std::cout methods for printing to the terminal, and a string holding the ascii art of the boat. From the lectures/tutorials, I already knew how to use the <iostream> standard methods (where std::cout is from).

Action:
Due to being a very simple problem, all I was required to do was find a way to represent the boat and then output this to the terminal. One way of doing this is through a series of std::cout statements outputting each individual line one by one to the terminal, separated by '\n' (newline/std::endl's). However, I decided instead to use a "R-String", also known as an raw string, represented by:
	std::string myBoat = R"(
/////////
/////////
/////////
)";
Where the '/' characters represent the space where the ASCII art is stored. I decided to use this approach as it would allow me to only use a single std::cout statement, by storing the boat art in a single string. I could alternatively have used a standard string which would follow the lines of:
	std::string myBoat = "/////////\n/////////\n/////////\n";
I chose to use the raw string approach, as c++ automatically formats in the newline (\n) characters to match what is written within the program itself. This allowed me to create the ASCII art within the code block, and have a visual representation of what would be outputted into the terminal.

I learnt of raw strings from my lecturer where he suggested the use for an in-tutorial task.

Results:
This use of an R-String worked successfully, and due to the simplicity of the problem, I did not encounter any issues when running my solution.

Learning:
I will continue to apply the use of R-Strings (raw strings) in most cases where ASCII is needed, as it makes constructing them, storing them and referencing them within the program much easier.


Challenge 2 - Reflection
Context:
This challenge asks to build an application which prompts the user for in-game details including name, username, clan tag and current xp number. It then uses input checking to ensure that the inputted data is valid. This application of input checking is the first time I have encountered such a process in c++, and thus I will be learning how to
properly do it in order to account for all edge cases of input. I expect this collection of number input to be the most difficult due to having previous issues with cin within my tutorial tasks.

Action:
I broke the problem down into 3 steps:
Data Collection
Data Manipulation
Data Output

Data Collection for the string variables involved prompting the user with a std::cout statement for what the program expects to recieve next, using getline(cin, stringVarName) to receive terminal input and then putting the inputted text through the following checks:
Checking if the string is empty - If so, output an 'error' message, and prompt the user for input again
Checking each character in the input, and checking whether any are non spaces. If every character is a space, this is counted as invalid and an 'error' message is also outputted, with the user prompted once again. If any character is not a space, we allow the input and continue onto the next variable prompt.

Data Collection for the int variable involved making a temporary string variable that I plan to parse through and ensure it is valid. I chose to use a temporary string variable due to encountering issues when the user would input strings, nothing, or just space characters into the cin prompt. This causes issues that are not consistent between the three of them when attempting to handle the failing input, and thus I believed parsing through the input myself would be the best catch-all solution. This involved using Booleans and looping through the inputted string to ensure there is only a single number present, with no spaces between digits, (no minus signs or decimal points as the number must end up as an unsigned int), but allowing for spaces before and after any present number. Should any invalidity be encountered during parsing, an error message is outputted, and the user is prompted again. If the parsing identifies the input as valid, it is then converted to an integer, and then used in the later steps.

Data Manipulation includes taking the inputted valid data and transforming it into further data we will need to provide the user in the Data Output step. This includes calculating what current level the user is at and deciding the remaining xp points to the next level. For this, I used integer division as it allows me to automatically truncate the value gained by playerXPPoints / xpPerLevel. For example, with 358 XP and 100 xpPerLevel, the result would be 3.58, which is converted to 3 through integer division. I chose to use integer division over manually flooring the value due to it being able to be automatically handled through the division, which reduces the amount of processes, and thus bloat in my program.

Data Output then included outputting this data in the exact format that the assessment required. This involved using simple std::cout (or cout, as I was using namespace std) statements as well as the << operator to properly format the terminal text.

Results:
The input parsing employed in the Data Collection step took a few iterations of solutions to work correctly, however at this point, it works correctly under any edge cases I have given it. It was unexpected the amount of issues I would face when trying to simply use the cin method when trying to input data and check it, however I was able to resolve said issues. I imagine should I research this further, there may be a more efficient or simpler solution to this problem, however given my current knowledge in c++, this is the most appropriate method I have found.

Learning:
This task has allowed me to understand how cin, input parsing and error checking works within a program, as well as the difficulties encountered in doing so. The solutions I designed within this program will likely be very helpful in reusing them within further tasks inside this assessment, my tutorials, and any other c++ projects. I also imagine a similar solution to input parsing could be applied to Task 8 where parsing a command for correct syntax within its command and variables is very important for proper function.
